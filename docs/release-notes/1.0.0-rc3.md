# TixoLink NEXUS 1.0.0-rc3 — Release Candidate

**Status: RELEASE CANDIDATE.** This is a hotfix release on top of
`1.0.0-rc2`: it fixes a release-blocking defect in the public
one-command bootstrap installer discovered by real (non-fixture)
validation performed after `1.0.0-rc2` was published. It has not been
exercised in production. CLI flags and the on-disk configuration schema
may still change before the final `1.0.0`.

## What's fixed since 1.0.0-rc2

- **Bootstrap HTTPS capability detection was broken, and silently
  blocked the one-command installer on essentially every real host.**
  `TixoLink.sh` checked for HTTPS support with a substring grep of only
  the *first line* of `curl --version`. Real curl output never puts
  protocol names on that line - they're listed on a separate
  `Protocols:` line further down - so the check failed against every
  real curl installation tested, including the host used to build and
  publish `1.0.0-rc2` itself. In practice, `1.0.0-rc2`'s public install
  command:

  ```
  TIXOLINK_CHANNEL=rc bash <(curl -fsSL https://raw.githubusercontent.com/TheTixoCloud/TixoLink/master/TixoLink.sh)
  ```

  unconditionally aborted with `"installed curl has no HTTPS support"`
  before ever contacting GitHub, regardless of channel or version
  selection. This did not surface in `1.0.0-rc2`'s test suite because
  every bootstrap unit test redefined the HTTPS-check function itself
  rather than exercising it against real `curl --version` output; it
  was only caught by a real (non-fixture) end-to-end bootstrap run
  performed against the published RC2 release, after RC2's Git tag and
  GitHub Release had already gone out.

  Fixed in `bootstrap::_curl_supports_https` by parsing the `Protocols:`
  line and requiring `https` as an exact space-separated token, instead
  of grepping the whole banner for a substring. New regression tests
  exercise the real function against realistic `curl --version` fixtures
  (supported; unsupported; an unrelated "https" substring elsewhere in
  the banner that must not false-positive; a missing `Protocols:` line;
  a failing `curl --version` invocation) and against this project's own
  build host's real, installed curl - closing the exact kind of gap that
  let the defect ship undetected in RC2.

- **Preflight assumptions audited.** Prompted by how this defect
  escaped testing, every other bootstrap preflight/environment check
  (root detection, OS/version detection, architecture detection,
  `sha256sum`/`tar`/`mktemp`/`awk`/`jq` presence and output-format
  assumptions, checksum-manifest parsing, archive-listing parsing) was
  re-verified against real Ubuntu 22.04/24.04 and Debian 12 command
  output. No further defects were found.

No application behavior changed otherwise: this release is `1.0.0-rc2`
plus the bootstrap fix above. See
[CHANGELOG.md](../../CHANGELOG.md) for the full itemized history and
[docs/release-notes/1.0.0-rc2.md](1.0.0-rc2.md) /
[docs/release-notes/1.0.0-rc1.md](1.0.0-rc1.md) for everything already
shipped before this hotfix.

## Was 1.0.0-rc2 usable?

**`1.0.0-rc2`'s one-command bootstrap installer (`TixoLink.sh`) did not
work on a real host of the kind it was designed for** - it refused
before ever reaching GitHub. The manual installation path (`git clone`
+ `sudo ./install.sh`) was unaffected by this defect and worked
correctly in `1.0.0-rc2`, as did everything installed that way
(including `tixolink update apply`, which does not use `TixoLink.sh` at
all). `v1.0.0-rc2`'s Git tag and GitHub Release remain published and
unmodified exactly as they shipped with this defect; this release does
not rewrite that history, it patches forward.

## GRE security warning

**GRE (IP protocol 47) DOES NOT PROVIDE ENCRYPTION.** Traffic inside a GRE
tunnel is only as confidential as the underlying network path. If you
need confidentiality, add an encryption layer (WireGuard, IPsec, TLS)
independently — TixoLink does not provide this and does not market GRE
as a VPN. Some networks filter protocol 47; plan accordingly.

## Important limitations

- **No artifact signing.** Both the bootstrap installer and
  `tixolink update apply` verify SHA256 integrity of what they download,
  not publisher authenticity of the release channel itself. See
  "Public bootstrap installer" and the updater's trust-model section in
  [docs/lifecycle.md](../lifecycle.md).
- **HAProxy forwarding is TCP-only.**
- This is RC3: it has not run in a production environment. Report issues
  via GitHub's private vulnerability reporting (security issues) or a
  public issue (everything else).

## RC status

This build is a release candidate: feature-complete for the scope
described above and passing the full unit/integration/lifecycle test
suite (including new regression tests for the bootstrap HTTPS-detection
fix), but not yet declared production-stable.
