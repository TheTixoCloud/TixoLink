# TixoLink NEXUS 1.0.0-rc1 — Release Candidate

**Status: RELEASE CANDIDATE.** This is the first build packaged as a
release artifact rather than an in-progress development snapshot. It has
not been exercised in production. CLI flags and the on-disk configuration
schema may still change before the final `1.0.0`.

## What TixoLink NEXUS is

TixoLink NEXUS manages Linux kernel tunnels (currently GRE over IPv4)
between a local server and a remote peer, and optionally forwards public
ports through the tunnel to a backend service. A single server can run
many independent, isolated tunnels at once.

## Supported platforms

- Ubuntu 22.04 LTS
- Ubuntu 24.04 LTS
- Debian 12
- Architecture: amd64/x86_64. The codebase avoids amd64-only assumptions
  where practical, but arm64 is not yet validated.

## Major capabilities in this candidate

- GRE IPv4 tunnel lifecycle (create/start/stop/restart/reload/edit/delete)
  with automatic `/30` inner-subnet allocation, interface-ownership
  checks, conflict detection, and transactional rollback.
- Peer export/import — a reviewed-before-applied, configuration-only JSON
  document for configuring the remote side of a tunnel.
- Port forwarding via pluggable engines: Netfilter (TCP/UDP) and HAProxy
  (**TCP only**), with mapping CRUD and engine migration.
- Diagnostics, latency/loss/throughput benchmarking (`iperf3` opt-in,
  never self-launched), and a live read-only monitor dashboard.
- A network optimizer and BBR manager built on a shared
  INSPECT→RECOMMEND→PREVIEW→APPLY→VERIFY→RESTORE model, with
  baseline-on-first-touch semantics so `restore` always returns to the
  administrator's original value.
- Full lifecycle: `install.sh`, `uninstall.sh` (default and `--purge`
  modes), `tixolink backup`/`restore`, `tixolink update check`/`apply`
  against GitHub Releases, and `tixolink factory-reset`.
- A non-interactive CLI surface for every command (flag-driven
  create/edit, scriptable automation) alongside the original interactive
  wizards/menu.

See [CHANGELOG.md](../../CHANGELOG.md) for the full itemized history and
[docs/architecture.md](../architecture.md) for the module breakdown.

## Installation summary

```
git clone https://github.com/TheTixoCloud/TixoLink.git
cd TixoLink
sudo ./install.sh
```

Installs to `/usr/local/bin/tixolink`, `/usr/local/lib/tixolink/`, and the
`tixolink@.service` systemd template; creates `/etc/tixolink/` and
`/var/lib/tixolink/` with defaults only if they don't already exist. No
tunnel is started automatically. See [docs/lifecycle.md](../lifecycle.md)
for upgrade, backup/restore, update, uninstall, and factory-reset
details, and for the sandboxed (`TIXOLINK_ROOT`) testing mechanism.

## GRE security warning

**GRE (IP protocol 47) DOES NOT PROVIDE ENCRYPTION.** Traffic inside a GRE
tunnel is only as confidential as the underlying network path. If you
need confidentiality, add an encryption layer (WireGuard, IPsec, TLS)
independently — TixoLink does not provide this and does not market GRE
as a VPN. Some networks filter protocol 47; plan accordingly.

## Before upgrading: take a backup

Because this is a release candidate, run `tixolink backup` (or let
`uninstall.sh --purge` take its automatic pre-purge backup) before
upgrading an existing installation to or past `1.0.0-rc1`. `update apply`
and `install.sh` never overwrite an existing `/etc/tixolink` or
`/var/lib/tixolink`, but a manual backup gives you an independent
restore point if a workflow outside TixoLink's own transactions goes
wrong. Older backups are never automatically deleted or overwritten.

## Important limitations

- **No artifact signing.** The updater and the release checksum manifest
  (`SHA256SUMS`) verify that downloaded bytes match what was published;
  neither authenticates that the release channel itself is
  uncompromised. See [docs/lifecycle.md](../lifecycle.md)'s trust-model
  section.
- **HAProxy forwarding is TCP-only.** HAProxy does not forward UDP in
  this configuration; use the Netfilter forwarder for UDP.
- Listing a crafted archive with an extreme gzip compression ratio can
  still cost CPU decompressing the gzip stream during `tar -tzf`, even
  though no extracted bytes are written to disk for that step — see
  "Archive resource limits" in [docs/lifecycle.md](../lifecycle.md).
- `restore` intentionally never starts, stops, or reloads a tunnel; it
  only rewrites on-disk config/state. Run `tixolink reload <id>`
  afterwards for any tunnel you want reconciled to the restored config.
- This is RC1: it has not run in a production environment. Report issues
  via GitHub's private vulnerability reporting (security issues) or a
  public issue (everything else) once the repository is published.
